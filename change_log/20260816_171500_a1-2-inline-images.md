# Change log — A1.2 Inline images in the editor body

**Date:** 2026-08-16
**Implements:** [`plans/20260816_163000_a1-2-inline-images.md`](../plans/20260816_163000_a1-2-inline-images.md)
**Idea:** A1.2 in [`docs/enhancement_ideas.md`](../docs/enhancement_ideas.md)

Images can now be put into the writing itself, not only listed in the attachment tray below it.

## What a user sees

- A new **image button** in the editor toolbar. It picks a file, refuses anything that is not an
  image, and drops the picture into the body where the cursor was.
- The picture is drawn in the flow of the entry. A menu under it sets **small, medium or full
  width**, and an ✕ removes it from the writing. Tapping it opens it full screen, where it can be
  zoomed.
- Removing an image from the body **does not delete the file** — it stays in the attachment tray,
  so it can be put back. Deleting for good is still the tray's job.
- A **locked** attachment shows a "Locked image — tap to unlock" box instead of the picture, and
  asks for the same device unlock the attachment tray asks for.
- Exports carry the picture: **HTML and PDF draw it into the page**, **Markdown links to the file**
  in the `attachments/` folder beside it, **plain text names it**. A locked image is left out of
  the page and reported in the "left out of this export" list.

## How it is built

The picture is an **ordinary encrypted attachment row**. The embed in the document holds only that
row's id:

```json
{"attachmentId": 12, "fileName": "beach.jpg", "widthFactor": 1.0}
```

That is the decision everything else follows from. Backup, sync, storage migration and export
already handle attachments, so an inline image inherits all of them, and no schema change was
needed. The embed type is `vault_image`, deliberately not Quill's built-in `image` type, which
would put the picture itself into `Entries.contentJson` — a column that is stored **unencrypted**.

## Files changed

### New

| File | What it does |
|---|---|
| `lib/features/entries/presentation/editor/image_embed.dart` | `VaultImageData` / `VaultImageEmbed` and the builder that draws it: the picture, the size menu, the delete button, and the locked / loading / unavailable boxes. Parsing never throws. |
| `lib/features/entries/presentation/editor/inline_image_store.dart` | Decrypts an attachment to a temp file **once** per screen, refuses locked ones until the prompt is answered, and deletes every decrypted copy on dispose. Pure Dart — every dependency arrives as a callback. |
| `test/features/entries/inline_image_store_test.dart` | 11 tests: caching, shared in-flight decryption, locks (including failing closed when the lock cannot be read), unavailable rows, and cleanup — including a decrypt that lands after the screen closed. |

## Deliberately not done

- **Drag-to-resize and cropping.** The three-step size menu covers the need.
- **Paste or drop an image into the editor.** Insertion is through the toolbar button.
- **`_handleAddAttachment` throws its picked file away** — the plain attachment button picks a
  file and never imports it. A real bug, found while reading this code, but it predates this work
  and deserves its own plan so its fix is logged on its own.
