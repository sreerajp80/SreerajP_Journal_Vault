# Change log — Review items 5–8: drawing re-edit, database access from widgets, sync SQL names, error text in logs

**Plan:** `plans/20260927_121959_review-items-5-to-8.md` (approved 2026-09-27, all items and slices,
Option A for item 8)

Done in the planned order: 8 → 7 → 5 → 6.

## Item 8 — Error text in logs (Option A)

- Eight log calls put the error into the message with `$e`. They now pass it as `error: e`:
  `ocr_camera_controls.dart` (2), `ocr_camera_source_store.dart` (2), `ocr_language_store.dart` (2),
  `platform_notification_service.dart` (2).
- `lib/core/logging/app_logger.dart`: the dev-only "full error" mode (`_fullErrors`) is removed.
  `warning`, `error` and `fatal` log only the error's type, in every flavor.
  `debugOverrideLogger` lost its `fullErrors` parameter.
- `test/core/logging/app_logger_test.dart`: the "dev logs the full error" test is replaced by one
  that checks `warning` and `fatal` log only the type.
- New guard test `test/core/logging/no_raw_error_in_log_message_test.dart`. It fails if any
  `AppLogger` message has `$e`, `$error`, `.message`, `.toString()` and similar in its text. It was
  checked against the old code, which it caught.
- `docs/security.md`: the logging section now says "type only, in every flavor".

## Item 7 — Sync SQL names

- New `lib/features/sync/services/sync_schema_guard.dart` (`SyncSchemaGuard`):
  - `isSyncable(table)` accepts only `SyncEngine.syncableTables`.
  - `knownColumns(table, data)` keeps only real columns of that table, read from Drift's own
    schema, never from the remote data.
- `sync_engine_records.dart`: `pull` skips any record whose remote or local table does not sync,
  and logs one count. Insert and update build their SQL only from known columns; a record with
  none left is skipped.
- `conflict_resolution_service.dart`: `_applyDataToRecord` skips a table that does not sync, and
  uses only known columns.
- New `test/features/sync/sync_schema_guard_test.dart`: table and column checks, including names
  with SQL in them, and a full pull where an `app_security` record is skipped while a journal
  record still applies. The tests were checked against a broken guard, and they failed as they
  should.
- Not changed here: the attachment path, the Keystore key name, and journal/entry ID mapping (review
  items 2–3).

## Item 5 — Drawing re-edit

- `entry_editor_actions_3.dart`: `_editDrawing` no longer deletes the old drawing. It records the
  old attachment ID in `_supersededDrawingIds`. The widget's direct DAO calls and its silent
  `catch (_) {}` are gone.
- `entry_editor_screen.dart`: `dispose` calls
  `EntryDeletionService.deleteUnreferencedAttachments` for those IDs, without awaiting it. The
  service is read in `initState`, because `ref` may not be used in `dispose`.
- `entry_deletion_service.dart`: new `deleteUnreferencedAttachments(entryId, ids)`. It reads the
  entry's **saved** text and deletes only the listed attachments of that entry that the saved
  text no longer shows. Unreadable saved text deletes nothing. It never throws.
- New `lib/features/entries/domain/attachment_ids_in_delta.dart`: a pure function that finds
  picture and drawing IDs in a delta. A test checks that its embed keys match the widget classes.
- Tests: three new cases in `entry_deletion_service_test.dart`, and
  `test/features/entries/domain/attachment_ids_in_delta_test.dart`.
- Accepted limit, as planned: after the editor closes, restoring a revision from before the
  re-edit shows the placeholder for the replaced drawing.

Details worth knowing:

- `EntryEditorService` and `IncomingEntryService` look up the attachment import service only when
  a file is added. Before this change the widgets read it only then too. Reading it up front broke
  four editor widget tests, which is how this was caught.
- `IncomingEntryService` gets the picture-embed shape from the widget as a function, so the
  service does not import editor widget classes.
- New guard test `test/architecture/no_dao_in_presentation_test.dart`. It fails if any file
  under `lib/**/presentation/` or `lib/app/` uses a DAO or `appDatabaseProvider`, apart from the
  start-up override in `app.dart`.
- New unit tests: `journal_service_test.dart`, `entry_editor_service_test.dart`,
  `tag_service_test.dart`, `user_template_service_test.dart`, `search_service_test.dart`,
  `incoming_entry_service_test.dart`, `attachment_storage_overview_service_test.dart`, and one new
  case each in `attachment_lock_service_test.dart` and `time_capsule_service_test.dart`.
- Docs: `docs/project_structure.md` (the `journals/` feature, and the services in `search/` and
  `tags/`), `docs/architecture.md` (data-flow rule, and a "Closed on 2026-09-27" section).

## Found along the way (not fixed — outside this plan)

- **Editor loses the last edits** (reported in the plan): `dispose` cancels the 2.5-second
  autosave, and nothing saves on leaving the screen. Needs its own plan.
- `entry_editor_widgets.dart`, "Linked from" row: an untitled entry shows the raw English text
  `'Entry #$sourceEntryId'`. That breaks the rule that UI text comes from the ARB files.
- An AirQR-received entry goes to journal ID `1` when the phone has no journals. That row does
  not exist, so the import fails with a foreign-key error. Behaviour kept as it was here.
- A stray backup copy of `sync_schema_guard.dart`, made while testing, is at
  `tmp_guard_bak` in the Git for Windows install folder (outside the project). A safety check
  blocked deleting it. It can be deleted by hand.
