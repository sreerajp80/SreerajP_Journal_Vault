# Change log: Rich paste (HTML) and rich table cells

**Plan:** `plans/20260924_223116_rich_html_paste.md`

## What changed

### 1. Table format v2 and export (Slice 1)

- New `lib/features/entries/domain/table_data.dart` (`TableData`, pure Dart). It reads all three
  table formats — the plain list, the envelope with column widths, and the new rich format
  `{"v":2,"rows":…,"cells":…,"colWidths":…}` — and writes the oldest format that can hold the
  table. `cells` holds each cell as Quill text ops with inline formatting only (bold, italic,
  underline, strike, code, link, colour, highlight, sub/superscript). `rows` always repeats the
  words as plain text, so an older app version still shows them.
- `TableEmbed` now reads and writes through `TableData`.
- **Bug fixed — resized tables did not export.** The export reader only knew the plain list
  format, so a table whose columns had been resized exported as "[unexportable block]". It now
  reads every format (`delta_document.dart`).
- Export keeps cell formatting: HTML/PDF cells use the same escaping and safe-link code as
  paragraphs; Markdown cells get `**bold**`, links and so on, with `|` escaped and a line break
  written as `<br>`. Plain-text export is unchanged (words only).

### 2. Rich table editing (Slice 2)

- Cells are drawn as formatted text. Tapping a cell opens a small live Quill editor for that one
  cell (`table_cell_editor.dart`). Tab / Shift-Tab, adding and deleting rows and columns, and
  column resizing work as before. A cell is written back when it is left.
- While a cell is being edited, the main formatting toolbar works on the cell; buttons that make
  no sense in a cell (headings, font, size, lists, indent, alignment, code block, quote, and the
  insert buttons) are greyed out (`editor_toolbar.dart`, new `table_cell_editing.dart`).
- The cell editor follows the Keyboard privacy switch.
- Links in cells open (http, https, mailto, tel only) in read-only views such as version history.
- **Two problems found and fixed while building this:**
  - flutter_quill writes a table back with `ignoreFocus`, which does not rebuild the table
    widget. A second write-back before the next rebuild used a stale document position and put a
    copy of the table at the top of the entry. The table builder now finds its new document node
    after every write-back. (The old table code had the same hidden weakness.)
  - flutter_quill's editor also receives every tap made on a table cell (its tap recognizer is
    "transparent" on purpose). Moving from one cell to another then made the entry editor and the
    old cell editor take focus from each other without end, freezing the app. The table now marks
    where a touch started, and the entry editor's `onTapDown` / `onTapUp` hooks ignore taps that
    started inside a table.
- The spike succeeded, so the bottom-sheet fallback in the plan was not needed.
- New string `labelTableCell` (the cell's accessibility label).

### 3. HTML paste converter (Slice 3)

- New `lib/features/entries/services/html_to_delta.dart` (`HtmlToJournalDelta`, pure Dart, never
  logs). It cleans the HTML (drops scripts, styles, images — keeping alt text — video, comments,
  Word `<o:p>`, and unwraps the Google Docs `<b>` wrapper), turns every table into a rich table
  block (header cells bold, `colspan` filled with blank cells, rows padded), then walks the rest:
  headings, bold / italic / underline / strike, sub/superscript, inline code, code blocks, quotes,
  nested lists, alignment, links. It reads Docs' numeric font weights and `vertical-align`.
- Safety clean-up: only `http`, `https`, `mailto` and `tel` links are kept; black, white and grey
  colours are dropped (unreadable in the other theme); font families and sizes are dropped.
- **Deviation from the plan:** the plan said to use `flutter_quill_delta_from_html` for the
  non-table parts. Testing showed it merges consecutive paragraphs into one line, ignores
  `<code>`, and returns colours in a different byte order. A small DOM walker of our own replaced
  it, so that package is **not** a direct dependency. Only `html` (the parser) is.

### 4. Paste hooked into the editors (Slice 4)

- New `lib/features/entries/presentation/editor/rich_paste_config.dart` (`RichPaste`). The entry
  editor, the template editor and each table cell editor use it through
  `QuillClipboardConfig.onClipboardPaste`. With HTML on the clipboard, Paste keeps formatting (in
  a cell: inline formatting only). Without HTML, the normal paste runs unchanged. One Undo removes
  a paste.
- New long-press menu item **Paste as plain text**, next to Paste as Markdown. New string
  `actionPastePlainText`.

### 5. Markdown tables keep cell formatting (Slice 5)

- `MarkdownToDelta` now keeps bold, italic, strike, code and web links inside table cells, for
  both "Paste as Markdown" and Markdown file import.

### 6. Table words are searchable (Slice 6)

- **Bug fixed — words in tables could not be found by search.** New
  `lib/features/entries/services/entry_plain_text.dart` (`entryPlainText`) gives the words inside
  tables instead of one placeholder character. It is used for the saved search text, the word
  count and smart-tag suggestions. Existing entries update the next time they are saved.
  Caret-offset code still uses Quill's own `toPlainText()`.

## Dependencies

- `html` (0.15.6) and `url_launcher` (6.3.2) are now listed directly in `pubspec.yaml`. Both were
  already in the app through `flutter_quill` (same versions in `pubspec.lock`), so no new code
  enters the build. `html` is a parser; `url_launcher` hands a link to the phone's browser. No
  network code is added. `docs/dependencies.md` updated.
