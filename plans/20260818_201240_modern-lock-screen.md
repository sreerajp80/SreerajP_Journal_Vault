# Modern app lock screen

**Status:** completed

## The issue

The lock gate (`_LockGateScreen` in `lib/app/app.dart`) is plain and unfinished looking:

- A default `AppBar` with the developer-ish title "App Lock Gate".
- Everything sits in a bare centred `Column` with no visual anchor.
- Phone-lock mode shows only a small mode label and one narrow button floating in
  a large empty page.
- App-lock mode shows a raw outlined `TextField` and a small button.
- Errors are raw red text with no icon or shape, using a hard-coded `Colors.red`
  that ignores the theme.

It does not look like the rest of the app and it is the first screen a user sees.

## The plan

Rebuild the lock gate as a modern, calm, full-screen unlock page. No change to any
unlock logic, provider call, or lock rule — only the presentation layer changes.

### New layout

1. **No `AppBar`.** The screen becomes full bleed, so the status bar area is part of
   the background.
2. **Soft gradient background** built from the current `ColorScheme`
   (`surface` → `surfaceContainerHighest` with a light `primary` tint), so it follows
   the seed colour and works in light and dark mode.
3. **Lock badge**: a large rounded circle using `primaryContainer`, holding a
   `Icons.lock_rounded` icon, with a wider soft ring behind it. This gives the page a
   focal point.
4. **Headline and subtitle**: the app name as the headline, then one short line saying
   the journal is locked, then a small "chip" showing the active mode
   (`Phone Lock` / `Separate App Lock`) with a matching icon.
5. **Unlock card**: a rounded, slightly raised container holding the mode-specific
   controls, width-capped at 420 px so it looks right on tablets and landscape.
   - **Phone lock**: a full-width `FilledButton.icon` with a fingerprint icon.
   - **App lock**: a filled, rounded, centred PIN field with number keyboard, a
     show/hide eye button, and a full-width `FilledButton.icon` "Unlock" below it.
   - While busy, the button shows a small progress indicator instead of its icon and
     is disabled (same `_busy` rule as today).
6. **Error area**: an error pill using `colorScheme.errorContainer` /
   `onErrorContainer` with a warning icon, replacing the hard-coded red text. It fades
   in with `AnimatedSwitcher` (a one-shot animation, so widget tests still settle).
7. **Entrance animation**: a single `TweenAnimationBuilder` fade + small upward slide
   when the screen appears. No repeating animation, so `pumpAndSettle` never hangs.
8. **Semantics** labels on the badge, the PIN field, and both unlock buttons.

### Kept exactly as-is (so tests and behaviour do not break)

- Widget keys `app-lock-pin-field`, `app-lock-unlock-button`,
  `phone-lock-unlock-button`.
- `_unlockPin` / `_unlockBiometric` logic, the `_busy` guard, and all error messages.
- The existing ARB keys `lockModePhone`, `lockModeApp`, `lockPinLabel`,
  `lockUnlockWithPhone`, `commonUnlock`, `lockAuthFailed`, `lockAuthUnavailable`,
  `lockEnterPin`, `lockIncorrectPin`.

### New localisation keys (with `@` descriptions)

| Key | English |
|---|---|
| `lockGateHeadline` | Your journal is locked |
| `lockGateSubtitle` | Unlock to open your entries. |
| `lockGateShowPin` | Show PIN |
| `lockGateHidePin` | Hide PIN |
| `lockGateBadgeSemantics` | Locked |

`lockGateTitle` ("App Lock Gate") stays in the ARB file — it is no longer shown, since
the app bar is gone. It is left in place rather than deleted so nothing else that may
reference it breaks.

## Files to change

- `lib/app/app.dart` — rewrite `_LockGateScreenState.build` and add small private
  widgets for the badge, the mode chip and the error pill. The screen stays in
  `app.dart` next to the other lock screens; moving it to
  `lib/features/lock_gate/presentation/` would be a larger refactor than this task
  needs.
- `lib/l10n/app_en.arb` — add the five keys above.
- `lib/l10n/app_localizations.dart`, `lib/l10n/app_localizations_en.dart` —
  regenerated by `flutter gen-l10n` (not hand edited).
- `test/app/lock_gate_screen_test.dart` — **new** widget test: phone-lock mode shows
  the unlock button and the headline, app-lock mode shows the PIN field, a wrong PIN
  shows the error pill.

No change to security rules, permissions, database, crypto, or the lock modes.
