# Plan: Offline P2P Local Wi-Fi Sync for SreerajP Journal Vault

**Status:** Proposed
**Author:** Antigravity
**Date:** 2026-08-24

---

## 1. Overview & Goal

SreerajP Journal Vault already contains a 392-line vector-clock based `SyncEngine`, `SyncEncryptionService`, and `ConflictResolutionService`, but is missing a physical transport implementation.

Based on the mature, battle-tested P2P LAN sync implementations in sibling apps (`SreerajP_TextApp` §2.8 / Phase 12, `SreerajPContactSphere` §6, and `sms-sentry` §8), this plan defines the implementation of **Offline Peer-to-Peer Wi-Fi Sync** in SreerajP Journal Vault.

It enables high-speed (10–50 MB/s), end-to-end encrypted transfer of journal entries, revisions, tags, and large encrypted attachments (audio notes, drawings, photos, PDFs) between devices on the same local Wi-Fi / hotspot with **zero servers, zero accounts, and zero cloud services**.

---

## 2. Architecture & Security Design

### 2.1 Threat Model & Security Posture
1. **Out-of-band Pairing:**
   - Host generates a fresh, high-entropy pairing code (~320 bits) using `Random.secure()`, drawn from an unambiguous character set (excluding look-alikes `0, O, 1, I, L`).
   - Pairing parameters (`sreerajp-journal-vault-sync://pair?v=1&h=<ip>&p=<port>&c=<code>`) are displayed via a local QR code and selectable text.
   - Screen showing the QR / pairing code is protected with `FLAG_SECURE`.
2. **Key Derivation & Sealing:**
   - Host generates a fresh 16-byte random salt per session, sent in the clear on socket connection (the salt is non-secret).
   - Both devices derive an AES-256 session key from the pairing code and salt using `PBKDF2-HMAC-SHA256` (300,000 iterations) or `Argon2id`.
   - Every wire frame after the salt is sealed with `AES-256-GCM`. An incorrect pairing code causes GCM tag decryption to fail immediately, rejecting the hostile or mismatched connection.
3. **Hostile-Peer Hardening (from `sms-sentry` / `SreerajP_TextApp`):**
   - Single-client lock on Host (subsequent connection attempts are dropped immediately).
   - `BoundedLineReader` enforcing strict size caps (`handshakeLineCap` = 4 KB, `payloadLineCap` = 100 MB) preventing socket buffer memory exhaustion.
   - Handshake timeout (15s), payload transfer timeout (120s), and automatic socket disposal on screen exit or idle disconnect.
4. **Android Permissions:**
   - Update `android/app/src/main/AndroidManifest.xml` to include `<uses-permission android:name="android.permission.INTERNET" />` and `<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />` to allow local socket binding and LAN IP discovery.

## 3. Proposed Changes & File Structure

### 3.1 Dependencies (`pubspec.yaml`)
- Add `qr_flutter: ^4.1.0` (BSD-3, render pairing QR code on Host).
- Add `mobile_scanner: ^7.2.0` (BSD-3, camera QR code scanner on Client).

### 3.2 Core Sync Services (`lib/features/sync/services/`)
- [NEW] `lib/features/sync/services/bounded_line_reader.dart`
  - Pure Dart buffered socket reader with byte-level line limits and timeout wrappers.
- [NEW] `lib/features/sync/services/wifi_sync_crypto.dart`
  - Pairing code generator, QR URI builder & parser, PBKDF2/Argon2id key derivation, and AES-256-GCM wire encryptor/decryptor.
- [NEW] `lib/features/sync/services/wifi_sync_constants.dart`
  - Protocol version, timeouts, QR schemes, line caps, and message headers.
- [NEW] `lib/features/sync/services/wifi_sync_transport.dart`
  - `WifiSyncHost`: Binds ephemeral port, emits host phases (`listening`, `connected`, `denied`, `stopped`), handles authentication handshake, and pushes payloads.
  - `WifiSyncClient`: Connects to host IP/port, executes authenticated handshake, and pulls/pushes sync payloads.
  - `localIpv4Addresses()` helper: Discovers non-loopback device LAN IPs for QR advertisement.
- [NEW] `lib/features/sync/services/wifi_sync_protocol.dart`
  - Concrete implementation of `SyncProtocol` connecting `SyncEngine` with `WifiSyncHost` and `WifiSyncClient`.
- [MODIFY] `lib/features/sync/services/sync_engine.dart`
  - Include attachment binary data packaging/extraction support in sync payloads (converting encrypted attachment file bytes to/from payload archives).

### 3.3 State Management & Providers (`lib/features/sync/providers/`)
- [MODIFY] `lib/features/sync/providers/sync_providers.dart`
  - Add `wifiSyncControllerProvider`, host state provider, and client connection notifier.

### 3.4 Presentation & UI (`lib/features/sync/presentation/`)
- [NEW] `lib/features/sync/presentation/sync_landing_screen.dart`
  - Mode selection: "Send / Host" or "Receive / Connect", with Wi-Fi network indicator and last synced info.
- [NEW] `lib/features/sync/presentation/sync_host_screen.dart`
  - Tab 1: QR Code, Host IP/Port, pairing code, live connection status chip, Stop button.
  - Tab 2: Sync scope selection (All journals or selective journals) and "Sync Now" trigger.
  - Applies `FLAG_SECURE` while pairing code is visible.
- [NEW] `lib/features/sync/presentation/sync_client_screen.dart`
  - Tab 1: QR Scanner (using `MobileScanner`) with auto-connect on scan.
  - Tab 2: Manual IP, Port, and Pairing Code entry with input validation.
  - Real-time connection & sync progress indicators.
- [MODIFY] `lib/app/app.dart`
  - Wire Settings → "Device-to-Device Sync" to `SyncLandingScreen`.

### 3.5 Localization (`lib/l10n/`)
- [MODIFY] `lib/l10n/app_en.arb` & `lib/l10n/app_ml.arb`
  - Add bilingual strings for Wi-Fi Sync UI, Host/Client status, QR scanning, errors, and progress.

## 4. Verification Plan

### Automated Tests
1. `test/features/sync/bounded_line_reader_test.dart`
   - Test line reading, line cap exceeded rejection, and timeout behavior.
2. `test/features/sync/wifi_sync_crypto_test.dart`
   - Test pairing code generation, URI encoding/parsing, key derivation, and AES-256-GCM encryption round-trip.
3. `test/features/sync/wifi_sync_transport_test.dart`
   - Test host/client socket handshake, correct code acceptance, wrong code denial, single-client lock, and payload exchange.
4. `test/features/sync/sync_engine_wifi_test.dart`
   - Test full bidirectional sync pass over local mock sockets including entries, tags, and encrypted attachments.
5. `flutter analyze` & `flutter test`

### Manual Verification
1. Launch Host on Device A, verify QR display and local IP address.
2. Launch Client on Device B, scan QR with camera.
3. Verify handshake completes and changes + attachments sync cleanly between devices.
4. Verify wrong pairing code rejects connection safely.
