# Editor: no Tab key, and bottom bars jump / cover the last line

**Status:** completed

## The issues

### 1. No way to type a Tab in the content editor

On Android the soft keyboard has no Tab key. `flutter_quill` only inserts a tab
character from a **hardware** key press (its `_handleTabKey` shortcut), and the
editor toolbar has no button for it. So on a phone there is no way at all to put
a tab in the body text.

### 2. Bottom bars jump and hide the line being typed

`entry_editor_screen.dart` builds the body as one `Column`:

```
title → toolbar → Expanded(editor) → EditorStatsBar → SmartTagChipBar
      → _MoodPickerRow → _LinkedFromPanel → _AttachmentTray → _BottomActionBar
```

Everything after `Expanded(editor)` steals height from the editor. Two problems
follow:

* **`SmartTagChipBar` is the "banner".** It is keyed on the live plain text, so
  it re-runs on every keystroke and resolves a moment after typing stops — the
  same moment the 2.5s auto-save fires, which is why it looks like an auto-save
  message. When it finds a match it grows from 0 to 48 px; when it finds none it
  shrinks back to 0. Each change resizes the editor, so the text jumps and the
  last line can end up hidden behind the bar.
* **The mood ("emotion") row is always on screen.** `_MoodPickerRow` is an
  unconditional child of the same `Column`, so it permanently eats a strip at
  the bottom even while the user is typing.

`_LinkedFromPanel` and `_AttachmentTray` have the same shape — they can appear
or change height at any time while typing.

## The plan

### Fix 1 — a Tab button in the editor toolbar

* `lib/features/entries/presentation/editor/editor_toolbar.dart`
  * Add an `onInsertTab` callback and an `IconButton`
    (`Key('editor-insert-tab')`, `Icons.keyboard_tab`) placed next to the
    existing indent / outdent buttons.
* `lib/features/entries/presentation/entry_editor_screen.dart`
  * Add `_insertTab()`: replace the current selection with `'\t'` through
    `_quillController.replaceText(...)` and move the caret one place on. Wire it
    to both `EditorToolbar` instances (normal and distraction-free).
  * Pass `enableAlwaysIndentOnTab: false` explicitly in `QuillEditorConfig` so
    a hardware Tab keeps inserting a real tab character (this is already the
    default; making it explicit stops a future package change from flipping it).
* `lib/l10n/app_en.arb` — new key `editorInsertTab` ("Insert tab") with its
  `@editorInsertTab` description. Then run `flutter gen-l10n`.

### Fix 2 — keep the area under the caret still while typing

* `lib/features/entries/presentation/entry_editor_screen.dart`
  * Add a listener on `_editorFocusNode` that calls `setState`, and a getter
    `_isTyping => _editorFocusNode.hasFocus`. Remove the listener in `dispose`.
  * While `_isTyping` is true, do **not** build `SmartTagChipBar`,
    `_LinkedFromPanel` or `_AttachmentTray`. They come back as soon as the
    editor loses focus. Nothing below the editor can then change height while
    the user types, so the jumping and the covered last line both stop.
  * `EditorStatsBar` stays visible — it has a fixed height and never resizes,
    so it cannot cover anything. Use `compact: true` for it in the normal
    screen too, to give the editor a little more room.
  * Move the mood picker off the screen bottom: delete `_MoodPickerRow` from
    the `Column` and open it from a new mood button in `_BottomActionBar`
    (`Key('entry-mood-button')`). The button shows the chosen emoji, or
    `Icons.mood_outlined` when no mood is set. Tapping it opens a modal bottom
    sheet holding the existing `_MoodPickerRow`, which keeps the current
    `entry-mood-picker` / `entry-mood-$level` keys so existing tests still find
    them. Picking a level updates `_mood`, marks the entry dirty and closes the
    sheet.
* `lib/l10n/app_en.arb` — new key `entryMoodTooltip` ("Set mood") with its
  description.

### Tests

* `test/features/entries/presentation/entry_editor_bottom_bars_test.dart` (new)
  * Tapping the toolbar Tab button inserts a `\t` at the caret.
  * With the editor focused, `entry-mood-picker` and the smart-tag bar are not
    in the tree; after focus is dropped they are.
  * Tapping `entry-mood-button` opens the sheet and shows the mood chips.
* Re-run the existing editor tests (`entry_editor_focus_test.dart`,
  `entry_editor_line_jump_test.dart`) plus `flutter analyze` and `flutter test`.
