# Plan: Rich paste (HTML) and rich table cells

**Status:** completed
**Change log:** `change_log/20260925_080418_rich_html_paste.md`

## Issue

### A. Pasting rich text loses formatting

When you copy from a web page, Google Docs, Word or Gmail and paste into an entry:

- **Tables are flattened.** Every cell becomes its own line. The table shape is gone.
- **Images from the page** become an `image` block the editor cannot show (and, if it did show
  them, they would load from the internet).
- **Page colours and fonts** come through as-is. A page's black text is invisible in dark mode.
- **Google Docs** wraps the whole copy in `<b>`, so the whole paste can turn bold.
- **Unsafe links** (`javascript:`, `file:`, `intent:`, `data:`) are kept as clickable links.

Why: Android apps *can* put HTML on the clipboard (the earlier "Paste as Markdown" plan wrongly
said they cannot), and the editor's normal **Paste** already reads it. The problem is the
converter it uses, `flutter_quill_delta_from_html` with default settings: it flattens tables, its
own table format is not ours, its "custom block" hook only sees top-level tags (Chrome and Docs
nest tables inside `<div>`/`<b>`) and runs a matched tag twice, and it does no clean-up.

### B. Table cells can only hold plain text

The table block stores one plain string per cell, and each cell is edited in a plain text box.
So bold, italic, colour and links cannot live inside a table — not from paste, not from Markdown,
and not when typing.

### C. Two existing table bugs found while planning

1. **Export drops resized tables.** Once you resize a column, the table is saved in the
   "envelope" format `{"rows":…, "colWidths":…}`. The export reader
   (`lib/features/export/services/delta_document.dart`, `_tableRows`) only reads the older plain
   list format, so a resized table exports as "[unexportable block]" in HTML, Markdown, plain
   text and PDF.
2. **Table text is not searchable.** Search text and word count come from
   `document.toPlainText()`, which turns every table into one placeholder character. Words inside
   a table can never be found by search.

## Fix

The work is split into six small slices, done and tested in this order.

### Slice 1 — Table data format v2 (model layer), and export reads every format

- `TableEmbed` (`lib/features/entries/presentation/editor/table_embed.dart`) learns a third
  format:
  ```json
  {"v": 2,
   "rows":  [["plain", "text"], …],
   "cells": [[[{"insert": "plain", "attributes": {"bold": true}}, …], …], …],
   "colWidths": [120.0, 200.0]}
  ```
  - `cells` holds each cell as a small list of Quill text operations (the same format the rest
    of the entry uses), with **inline formatting only**: bold, italic, underline, strike, inline
    code, link, text colour, highlight, subscript, superscript. A cell may have more than one
    line. No headings, lists, images or tables inside a cell.
  - `rows` always holds the same cells as plain text. This keeps **older app versions working**
    (for example a second device on Wi-Fi Sync that has not been updated yet, or a backup opened
    in an older version): they read `rows` and ignore `cells`. If an older version *edits* the
    table, it saves plain text only, so that table loses its cell formatting but keeps its words.
  - The old list format and the envelope format still load. A table is only written as v2 when
    something is saved to it; a table with no formatting anywhere is still written in the old
    formats, so existing entries do not change for no reason.
- The pure table-reading code moves out of the widget file into a small model class in the
  domain layer, `lib/features/entries/domain/table_data.dart` (no Flutter), so the editor,
  export, paste and Markdown code all read tables the same way.
- **Export** (`delta_document.dart`) uses that model, so it reads all three formats — this fixes
  bug C1. `TableBlock` changes from plain strings to rich cells (a list of text runs per cell).
  - **HTML / PDF export:** cell text keeps its formatting, using the same escaping and safe-link
    code the paragraphs already use.
  - **Markdown export:** `**bold**`, `*italic*`, `~~strike~~`, `` `code` `` and `[text](url)`
    inside cells; `|` is escaped and a line break in a cell becomes `<br>`.
  - **Plain text export:** words only, as today.

### Slice 2 — Rich table editing (presentation layer)

- Each cell is **shown** as formatted, read-only text. Links in a cell open the same way as
  links in the entry.
- **Tapping a cell** turns just that one cell into a small live Quill editor (only one live cell
  at a time, so a 30-row pasted table stays fast). Everything that works today stays: Tab /
  Shift-Tab to move between cells, Tab on the last cell adds a row, add / delete row and column,
  column resize, and saving the cell when you leave it (one undo step in the entry, as today).
- **While a cell is being edited, the main editor toolbar works on the cell.** Bold, italic,
  underline, strike, sub/superscript, text colour, highlight, inline code and link act on the
  cell's text. Buttons that make no sense inside a cell (headings, font, size, lists, indent,
  alignment, code block, quote, table, callout, image, drawing, scan) are greyed out. Leaving
  the cell gives the toolbar back to the entry.
- The cell editor passes `enableIMEPersonalizedLearning: KeyboardPrivacyScope.allowLearning(context)`,
  so the Keyboard privacy switch still applies.
- Read-only views (version history, time capsule, entry detail) show formatted cells.
- **Risk and fallback.** A live Quill editor inside another Quill editor's block may fight over
  taps or focus. I will test this first. If it cannot be made reliable, the fallback is: tapping
  a cell opens a small bottom sheet with a cell editor and a mini toolbar (bold, italic,
  underline, strike, colour, link). Same stored format, same everything else. I will tell you
  before switching to the fallback.
- No new strings are expected for this slice (existing toolbar tooltips are reused). If one is
  needed it goes into all three ARB files.

### Slice 3 — HTML paste converter (services layer, pure Dart)

`lib/features/entries/services/html_to_delta.dart` — class `HtmlToJournalDelta`,
`Delta convert(String html)`:

1. **Parse** with `package:html`. Keep only `<body>`. Remove `<script>`, `<style>`, `<meta>`,
   comments and Office noise (`<o:p>`, `mso-` styles). Unwrap Google Docs'
   `<b id="docs-internal-guid-…">` wrapper instead of making everything bold.
2. **Tables.** Find every outer `<table>` (at any depth). For each `<tr>`, read each `<th>` /
   `<td>` as a **rich cell**: its inline formatting and links are kept (same clean-up rules as
   below); `<th>` text is made bold; `<br>` and `<p>` inside a cell become line breaks;
   `colspan` adds blank cells so every row is the same width. Replace the table with a
   placeholder, convert the rest, then swap the placeholder for a v2 `TableEmbed`. A table
   inside a cell is read as its text.
3. **Everything else** goes through `HtmlToDelta` from `flutter_quill_delta_from_html`
   (headings, bold / italic / underline / strike, sub/superscript, inline code, code blocks,
   quotes, nested bullet / numbered / check lists, alignment, links).
4. **Clean-up pass** (applied to body text and to table cells):
   - **Links:** keep `http`, `https`, `mailto`, `tel`. Anything else, and in-page `#anchors`,
     keeps the text but loses the link.
   - **Images / video:** removed; an image's `alt` text is kept. Nothing is fetched from the
     internet. (Saving pasted images as encrypted attachments could come later.)
   - **Colours:** kept only when they are a real colour. Black, white and greys (the page's
     default text and background) are dropped so text stays readable in light and dark theme.
   - **Font family and font size:** dropped; the app's fonts (including the bundled Malayalam
     and Devanagari fonts) are used. Headings still come through as headings.
   - Any attribute the editor does not know is dropped. The result ends with a newline.
5. If parsing fails, the paste falls back to plain text. Pasted content is **never logged** —
   only a fixed message such as `"HTML paste fell back to plain text"`.

### Slice 4 — Hook paste into the editors (presentation layer)

- The entry editor (`entry_editor_screen.dart`) and the template editor
  (`template_editor_screen.dart`) get a controller config with
  `QuillClipboardConfig(onClipboardPaste: …)`, built by one shared helper
  `lib/features/entries/presentation/editor/rich_paste_config.dart`. The handler reads the
  clipboard HTML through flutter_quill's `ClipboardServiceProvider` (what the editor already
  uses). If there is HTML, it converts it and inserts it at the cursor, replacing any selection,
  as one undo step. If there is no HTML, it returns "not handled" and today's paste runs
  unchanged.
- **Pasting inside a table cell:** the cell editor gets the same handler, but keeps only inline
  formatting (a pasted table or list is pasted into the cell as text lines).
- **"Paste as plain text"** is added to the long-press menu next to "Paste as Markdown", for
  when you want only the words. New ARB key `actionPastePlainText`, with an `@` description:
  - en: "Paste as plain text"
  - ml: "സാധാരണ ടെക്സ്റ്റായി ഒട്ടിക്കുക" — needs native-reader review
  - sa: "केवलपाठरूपेण स्थापय" — needs native-reader review

  Then `flutter gen-l10n`.

### Slice 5 — Markdown tables keep cell formatting

`lib/features/entries/services/markdown_to_delta.dart` currently strips `**bold**`, links and so
on from table cells. It now keeps them as rich cells (v2 table). This also improves
"Paste as Markdown" and Markdown file import. Safe-link rules are the same as in Slice 3.

### Slice 6 — Table text becomes searchable (fixes bug C2)

`TableEmbedBuilder` gets a `toPlainText` that returns the cells' words (cells separated by
spaces, rows by new lines). The places that build an entry's search text and word count
(`entry_editor_screen.dart`, `entry_editor_actions.dart`, `entry_editor_actions_2.dart`) pass the
editor's embed builders to `document.toPlainText(…)`. Result: words in tables are found by
search and counted in the word count. **Existing entries update the next time they are saved**
— no background re-index, no schema change.

## Dependencies

`flutter_quill_delta_from_html` (1.5.3) and `html` (0.15.x) are **already in the app** through
flutter_quill. Our code will import them directly, so they are added to `pubspec.yaml` as direct
dependencies at the versions already in `pubspec.lock`. No new code enters the build. Checked:
`flutter_quill_delta_from_html` depends only on `dart_quill_delta` and `html` — no network code.
`docs/dependencies.md` gets a line for each.

## Not changing

- No database schema change and no migration: the table lives inside the entry's content JSON.
- No new network use; pasted images are dropped, never loaded.
- "Paste as Markdown" stays; the share-to-app quick capture is unchanged.
- **Keyboard clipboard strip** (Gboard / Samsung) still pastes plain text only — the keyboard
  sends plain text, which no editor can change. Rich paste works from the long-press **Paste**.
